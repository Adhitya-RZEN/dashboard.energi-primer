## 4. /login Nonce Remediation

The /login App Router page now exports dynamic = force-dynamic. This keeps
the route on the request-time rendering path so the framework can attach the
same request-specific nonce to generated scripts/styles and the response CSP
candidate. The nonce is not hard-coded, stored in a database, placed in an
environment variable, persisted between requests, or printed in diagnostics.

The verification harness compared only bounded nonce presence and hashes. It
did not print raw nonce values.

## 5. Dynamic Style Remediation

The six application-level inline style expressions were converted to finite
CSS class mappings or native browser properties. Chart geometry uses fixed
class variants, chart colors use finite token classes, tooltip colors use
finite border/background classes, and the target progress display uses a
native progress element with stylesheet pseudo-elements.

The local dependency patch also removes generated inline style paths from the
pinned Recharts wrapper/surface/measurement code and the Next.js route
announcer. The patch is exact-version guarded and idempotent.

## 6. CSP Candidate

The candidate policy used only for the local Report-Only runtime was:

```

img-src 'self';

connect-src 'self';
frame-src 'none';
```

The candidate contains no unsafe-inline, unsafe-eval, wildcard, or broad
data/blob source. It remained Report-Only and loopback-only throughout this
phase. It was not added to the Production response header.
